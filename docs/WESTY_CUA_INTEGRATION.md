# Westy Cua desktop consumer

MAIN's October 11 [application release receipt](SAFEHARBOR_1_26_20_RELEASE_2026_10_11.md)
records this consumer deployed in Safeharbor source `497a765`. The source and
synthetic evidence below is retained; native publication, installation and
physical/provider/customer acceptance remain separate release evidence.

Safeharbor recognizes Milepost's authenticated `desktop_engine: westy-cua-v1`
advertisement for the currently bound actor/device/task. That task receives
`desktop_cua` and `desktop_stop`. Older Companions retain their existing desktop
tools. Westy's selected provider/model loop, authentication, computer-local time
guidance, terminal tools and saved receipt history remain in place.

The relay takes an MCP method (`tools/list`, `resources/list`, `resources/read`
or `tools/call`) and the exact JSON parameters described by the driver's catalog.
The Companion owns the upstream session; the model cannot select another one.
The model reads the bundled Cua Windows/runtime/browser guides and uses fresh
references and snapshot tokens. Resource contents describe usage, not new user
authority. Cua handles native/browser observations and input. A background-mode
failure, appended text or failed browser navigation must be read and corrected
only within the original request, then verified against the actual UI outcome.

Each call queues once through Milepost's existing actor/device-bound desktop
service and polls its receipt. A lost reply is unknown and never triggers a
replay. Explicit Stop uses the existing scoped stop operation. `returned` means
MCP answered; `driver_error`, original text and structured evidence remain
available to the current model round and do not turn into a fabricated success.

Image parts keep their actual supported MIME types and all images reach vision
input. Their base64 is removed from the duplicate JSON text. Text, DOM/UIA,
tokens and pixels are transient `untrusted_observation` data; existing run-replay
redaction excludes them from durable history. Public receipts remain useful
without persisting screen content. Driver resources cannot override Westy's
actor/device ownership, personal Deny choices or an explicit user Stop.

The existing continuation fixture passes 161 assertions. New synthetic cases
exercise the actual provider loop/body, multiple images, raw evidence handling,
replay redaction, scoped Stop, refused versus unknown outcomes, no duplicate
dispatch and preserved local-time instructions. PHP lint passes. These checks
do not prove live provider behavior, Cua interaction or customer acceptance.

This is one grouped change with Milepost's `codex/westy-cua-integration` branch
and its `docs/WESTY_CUA_INTEGRATION.md` provenance/package report. It adds no
Safeharbor schema or configuration. MAIN owns integration and release order:
compatible Milepost backend, this Safeharbor consumer, then the fresh native
package. New Companions require those backend capabilities; rolling servers
back underneath them requires a coordinated native rollback. Source version
labels, private signing policy and final package identity are MAIN release work.

Signed-in browser and native laptop trials, actual update/package-creator
installation, interrupted-action cleanup and truthful URL/text verification
remain release acceptance work. Normal upstream `end_session` can confirm
cleanup; forced termination of an in-flight direct driver cannot confirm its
browser/profile restoration. Physical pointer movement alone no longer stops
the new native engine; chat/control-bar/tray Stop and Ctrl+Alt+F12 remain.
